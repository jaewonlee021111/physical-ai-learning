공개 교안을 바탕으로 작성한 복습 노트입니다. 개인 출석·제출 완료를 뜻하지 않습니다.

## 핵심 정리
- 채팅 답변과 파일을 읽고 수정하고 실행하는 코드 에이전트의 작업 범위를 구분한다.
- 선택한 도구 하나에서 프로젝트 폴더를 열고 읽기 → 계획 → 수정 → 실행 → 검토 순으로 작업한다.
- 요구사항은 기능 목록뿐 아니라 정상·실패 상황과 완료 조건을 포함한다.
- 수업의 프로젝트 주제는 실습실 장비 대여 프로그램이다. 대여·반납·저장 기능과 검사 기록을 남긴다.
- 화면·데이터·함수의 연결을 설계한 뒤 작은 작업으로 나눠 요청한다.
- README는 실행·사용 안내, 설계 문서는 구조와 판단 근거, 작업 기록은 변경·시험·남은 일을 담는다.
- 프로젝트 지침은 해당 프로젝트의 규칙, Skill은 재사용할 절차, MCP는 외부 도구·데이터를 연결하는 방식이다.
- MCP 연결 표시만으로 실제 조회 성공을 입증할 수 없다. 요청·응답·확인 시점을 기록한다.
- 변경 요청 후 diff와 실행 결과를 확인하고 다음 작업자에게 컨텍스트를 넘긴다.

## 요구사항 예시
| 상황 | 기대 결과 |
| --- | --- |
| 대여 가능한 장비 대여 | 상태가 대여 중으로 바뀌고 기록 저장 |
| 이미 대여 중인 장비 재대여 | 거절하고 기존 상태 보존 |
| 대여 중인 장비 반납 | 대여 가능 상태로 변경 |
| 없는 장비 ID 입력 | 명확한 오류 안내 |
| 저장 후 재실행 | 이전 기록 복원 |

위 사례를 포함한 장비 대여 프로그램을 구현했다. [소스·실행 안내](../projects/equipment-loan/README.md)와 [실제 검증](../evidence/validation.json)을 확인한다.
