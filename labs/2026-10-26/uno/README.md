# UNO · 9개 독립 실습

UNO/ATmega328P용이다. ESP32의 3.3V 회로에 이 5V 배선을 그대로 적용하지 않는다. **아래 모드는 각기 별도 회로**이며, 전원을 뺀 뒤 배선을 바꾼다. 같은 핀이 여러 실습에서 반복되는 것은 동시에 연결한다는 뜻이 아니다.

## 배선표

| 모드 | UNO → 부품 | 확인할 것 |
|---|---|---|
| check | USB만 연결 | 내장 LED·`UNO_READY`·하트비트 |
| rgb | D9 → 1kΩ → R, D10 → 1kΩ → G, D11 → 1kΩ → B, GND → 공통 − | 채널마다 저항, 공통 음극 모듈 기준 |
| lcd | 5V → VCC, GND → GND, A4 → SDA, A5 → SCL | I2C 백팩 모델·주소·대비 조절 |
| climate | LCD 배선 + D2 → DHT11 DATA, 5V/GND → 모듈 전원 | 모듈 핀 이름, 벌크 센서는 별도 풀업 필요 여부 |
| joystick | 5V/GND → +5V/GND, A0 → VRx, A1 → VRy, D2 → SW | D3 버튼 → GND는 점프, D6 버튼 → GND는 공격; INPUT_PULLUP |
| keypad | D2~D5 → R1~R4, D6~D9 → C1~C4 | 실물 커넥터의 행·열 순서 대조 |
| piano | keypad 배선 + D10 → 수동 피에조 +, GND → − | 누르는 동안 재생, 떼면 정지 |
| ir | D2 → OUT, 5V → Vs, GND → GND | 수신 소자의 모델별 핀 순서는 반드시 확인 |
| sound | 5V → VCC, GND → GND, A0 → AO | DO와 AO를 혼동하지 않음 |

빵판은 같은 숫자의 A~E가 한 묶음, F~J가 다른 묶음이다. 가운데 홈을 건너면 연결되지 않는다. 저항 양끝을 같은 묶음에 꽂으면 저항을 우회한다. 회로의 연결 대상이 같으면 빈 구멍으로 옮길 수 있으며 수업 그림의 좌표를 반드시 똑같이 쓸 필요는 없다.

## 빌드·업로드

저장소 루트에서:

```sh
python -m pip install platformio==6.2.0 pyserial==3.5
python -m platformio device list
python -m platformio run -d labs/2026-10-26/uno -e check
python -m platformio run -d labs/2026-10-26/uno -e check -t upload --upload-port COM본인포트
python -m platformio device monitor --port COM본인포트 --baud 115200
```

`-e check`를 표의 모드로 바꾼다. 업로드 전 다른 모니터·웹 게임의 시리얼 연결을 닫는다. COM 번호는 본인 장치 기준이며 macOS/Linux는 실제 장치 경로를 쓴다. 새 펌웨어를 업로드하면 이전 모드를 대체한다.

## RGB·LCD·온습도 시계

RGB는 모니터에서 `RGB 255 80 0`과 줄바꿈을 보내거나 아래 도구를 쓴다. 1초 켜지고 1초 꺼지는 점멸을 반복한다.

```sh
python labs/2026-10-26/tools/serial_console.py --port COM본인포트 rgb 255 80 0
python labs/2026-10-26/tools/serial_console.py --port COM본인포트 clock
```

`clock`은 **climate 모드 업로드 후** 실행한다. 포트를 열면 UNO가 리셋될 수 있어 2초 후 현재 PC 시각을 보낸다. UTC Unix 초는 보드에서 +9시간 해석하여 KST로 표시한다. PC 시계가 정확해야 하며 RTC·NTP가 없는 `millis()` 기반 시계는 장시간 오차가 생길 수 있다. 전원 재인가 후에는 다시 동기화한다.

LCD 1행은 `MM/DD HH:MM:SS`, 2행은 온도·습도다. 연도를 포함한 시각은 시리얼에도 출력한다. 시계는 매초, DHT11 측정은 2초마다 갱신한다. 읽기 실패 시 오류 문구를 내고 가짜 측정값을 넣지 않는다. LCD는 일반적인 0x27/0x3F 주소를 탐색하며 다른 주소·백팩이면 코드·라이브러리 매핑을 조정한다. 백라이트만 켜지고 글자가 없으면 배선·주소와 뒷면 대비 가변저항을 확인한다.

## 키패드 피아노

키 번호는 물리 인쇄가 아니라 **행 우선 1~16**이다. 흔한 키패드의 첫 행 `1 2 3 A`는 코드의 1~4, 다음 행 `4 5 6 B`는 코드의 5~8이다. 제품에 따라 커넥터의 행·열 순서가 달라진다.

| 키 번호 | 음계 | 주파수 Hz | 키 번호 | 음계 | 주파수 Hz |
|---|---|---:|---|---|---:|
| 1 | C4 도 | 262 | 9 | D5 레 | 587 |
| 2 | D4 레 | 294 | 10 | E5 미 | 659 |
| 3 | E4 미 | 330 | 11 | F5 파 | 698 |
| 4 | F4 파 | 349 | 12 | G5 솔 | 784 |
| 5 | G4 솔 | 392 | 13 | A5 라 | 880 |
| 6 | A4 라 | 440 | 14 | B5 시 | 988 |
| 7 | B4 시 | 494 | 15 | C6 도 | 1047 |
| 8 | C5 도 | 523 | 16 | D6 레 | 1175 |

입력을 안정화한 뒤 한 음만 재생한다. 여러 키가 감지되면 거부하며 다이오드 없는 키패드에서 화음을 지원한다고 주장하지 않는다. 일반 패시브 피에조용이며 액티브 부저는 원하는 음계를 재생하지 못할 수 있다.

연주 연습(가사 없는 전통·고전 선율, 숫자는 위 표의 키 번호; `|`는 구간, `-`는 길게):

- 반짝반짝 작은 별: `1 1 5 5 6 6 5- | 4 4 3 3 2 2 1- | 5 5 4 4 3 3 2- | 5 5 4 4 3 3 2-`
- 환희의 송가: `3 3 4 5 | 5 4 3 2 | 1 1 2 3 | 3- 2 2- | 3 3 4 5 | 5 4 3 2 | 1 1 2 3 | 2- 1 1-`

## IR·소리 모듈

IR은 프로토콜·주소·명령·반복 상태를 시리얼에 출력한다. 리모컨 버튼마다 코드가 다르므로 특정 숫자가 반드시 같은 기능이라고 하드코딩하지 않았다. 이 모드는 피아노와 별개이며 IR 수신과 tone의 타이머 충돌을 동시에 다루는 회로가 아니다.

소리 모드는 50ms 구간에서 DC 평균을 빼고 RMS를 구한다. 표시 `dBFS = 20 log10(RMS / 511.5)`는 ADC full-scale 대비 상대값이다. 마이크 감도·증폭률·주파수 응답·기준 음압 교정이 없으므로 **실제 dB SPL이 아니다**. `THRESH 40`은 소프트웨어 RMS ADC 임계값이며 모듈의 가변저항이나 DO 임계값과 다르다. ANSI 지원 터미널은 알람을 색으로 표시하지만 일반 시리얼 모니터는 이스케이프 문자가 보일 수 있다. 숫자·`ALARM` 텍스트는 색 없이도 읽을 수 있다.

```sh
python labs/2026-10-26/tools/serial_console.py --port COM본인포트 monitor
```
