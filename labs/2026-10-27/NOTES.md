# 10/27 강의 핵심

## MQTT와 무선 센서 연결

보드가 센서 상태를 발행하고, 웹이나 휴대폰이 구독한다. 반대로 웹·휴대폰은 LED 명령을 발행하고 보드는 구독한다. 브로커가 두 방향을 중계하므로 각 장치가 서로의 주소를 모두 알 필요가 없다. 강의에서는 Mosquitto와 스마트폰 MQTT 앱을 활용했다.

토픽은 주소 역할, payload는 내용이다. 구독 성공·브로커 전송·보드 코드 적용·실제 LED 점등은 서로 다른 관찰이다. QoS 1에는 중복 전달 가능성이 있어 명령 ID로 중복 처리를 막는다. retained 값은 새 연결에 과거 상태를 전달할 수 있으므로 수신했다고 즉시 현재 상태로 판단하면 안 된다.

MQTT는 작은 센서 메시지와 발행·구독에 유용하지만 HTTP보다 모든 상황에서 빠르거나 좋은 것은 아니다. ESP-NOW, mesh, WSN(무선 센서 네트워크), gateway/sink 개념도 소개됐다. ESP-NOW를 사용한다는 사실만으로 mesh 라우팅까지 구현되는 것은 아니다. 이 폴더는 mesh 구현을 포함하지 않는다.

## 백엔드 구조와 CRUD

클라이언트 요청을 API endpoint가 받고 DB의 데이터를 처리해 응답한다. path는 자원 식별, query는 검색·선택 조건, body는 생성·수정 데이터에 사용한다. GET은 조회, POST는 생성·작업 요청, PUT은 전체 교체, PATCH는 부분 수정, DELETE는 삭제다. 성공·입력 오류·미인증·권한·자원 없음의 상태 코드를 구분한다.

처음에는 FastAPI와 SQLite로 아이템 CRUD를 만들고 Swagger에서 시험했다. 이후 routers(경로), schemas(입출력 검증), services(DB 처리)로 나눴다. FastAPI Depends는 공통 인증·DB 접근을 경로 함수에 전달한다. 용어를 검색하고 퀴즈·오답을 복습하는 학습 웹 페이지도 제작 과제에 포함됐다.

## 로그인과 권한

회원가입 시 비밀번호는 Argon2로 해시한다. 로그인 성공 시 발급한 JWT를 Bearer 헤더로 전달한다. 서명은 변조 검증이며 payload를 암호화하는 기능은 아니다. 만료·발급자·대상도 검사해야 한다. 인증은 누구인지 확인하는 것이고, 인가는 그 사용자가 이 데이터를 변경할 수 있는지 확인하는 것이다. 소유자 ID를 사용자가 보낸 body에서 믿지 않는다.

CORS는 브라우저의 교차 출처 접근 정책이다. 로그인이나 접근권한을 대신하지 않는다. 실제 서비스에는 요청 제한·비밀번호 재설정·메일 검증·토큰 폐기·관찰과 백업 같은 추가 설계가 필요하다. 이 예제는 학습용 최소 구현이다.

## 외부망에서 보드 제어

강의에서는 FastAPI·Supabase·웹 화면·ESP32를 연결하고 프런트엔드와 백엔드를 배포해 휴대폰 외부망에서도 제어하는 흐름을 다뤘다. DB 접속 정보와 기기 키는 서버·보드에 두고 공개 웹 자바스크립트에 넣지 않는다. 웹은 사용자 토큰, 보드는 개별 기기 키를 사용한다.

재구성 예제는 사용자 소유 보드에 명령을 큐잉하고 보드가 polling → 적용 → ACK하도록 했다. 기본 SQLite와 선택적 Supabase PostgreSQL 저장소를 지원한다. **Supabase Auth를 복제한 구현은 아니다.** 사용자 인증은 FastAPI의 로컬 JWT다. 명령은 30초 후 만료되며 만료 정리는 보드 조회 시 수행한다. ACK는 보드 소프트웨어의 응답이고 LED를 광학 센서로 측정한 증거가 아니다.

## TinyML과 데이터 수집

Edge Impulse 계정·API 키 준비와 TinyML 개념을 소개한 뒤 ESP32 카메라 사진을 모으는 화면을 만들었다. 클래스 이름, 한 장 촬영·스페이스바, 연속 촬영, 잘못된 사진 삭제, ZIP 다운로드가 핵심이다. 콜라·칙촉 사례처럼 배경·거리·각도·조명을 바꿔 모으되 비슷한 연속 사진을 나눠 높은 평가 점수를 만드는 오류를 주의한다. 학습·평가·추론의 본격적인 연결은 다음 날로 이어졌다.
